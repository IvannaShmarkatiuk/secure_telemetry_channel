# secure_telemetry_channel

Захищений канал телеметрії з обмеженою пропускною здатністю. Проєкт 1, дисципліна «Алгоритми і оптимізація програмних рішень», команда T01.

Передавач: кадри → перцептрон (клас кадру) → рюкзак ДП (які кадри в пакет) → стиснення Гаффмана → пакет TLM1 (AES-256-CTR + HMAC-SHA256) → планувальник (порядок відправлення) → модель каналу → приймач → ті самі кадри. Генетичний алгоритм підбирає параметри передавача. Формат пакета — строго за `FORMAT_SPEC.md`, модель каналу — `channel.py` від викладача (не змінюється).

## Вимоги

- Python 3.10+
- залежності: `pip install -r requirements.txt` (pytest, cryptography, numpy)
- numpy використовується тільки для арифметики масивів (множення матриць); прямий прохід, backprop і SGD перцептрона в `src/classifier.py` написані самостійно, бібліотек навчання (sklearn, torch тощо) немає.

## Запуск однією командою

Усі команди виконуються з кореня репозиторію.

```
pip install -r requirements.txt
python src/evaluate.py
```

`evaluate.py` проганяє сеанс із `data/session.bin` (3000 кадрів) через три сценарії каналу у трьох варіантах — baseline (послідовне пакування), поточна система (рюкзак ДП + перцептрон) і параметри, знайдені GA, — друкує S, R, T, Q і перевірку порогу втрат критичних кадрів, а також зберігає `results/final_metrics.json`. Займає близько 10 с. Підсумок виводу:

```
Q (середнє за сценаріями): 0.6903  baseline (послідовне)
Q (середнє за сценаріями): 0.5954  поточне (рюкзак ДП + MLP)
Q (середнє за сценаріями): 0.6918  GA (вікно 39, бонус 12, аномалія 4)
```

T, а отже й Q, залежить від швидкості машини; S, R і кількість пакетів відтворювані (seed каналу фіксований).

python -m pytest -v                                # усі тести (~25 с)

## Рішення щодо неоднозначностей FORMAT_SPEC

Специфікація не визначає ці випадки однозначно, тому команда вирішила так:

1. **Розділ 7, «31 біт».** Вважаємо опискою: байти `0C E6 DF 90` містять 30 біт даних і 2 нулі доповнення.
2. **Ненульові біти доповнення** → `E_CODE` (помилка в бітовому потоці, розділ 3.3).
3. **Таблиця довжин із сумою Крафта ≠ 1** → `E_CODE`. Виняток: один символ із довжиною 1 (сума ½), дозволений розділом 3.2. Код Гаффмана завжди дає повне дерево; на всіх еталонних пакетах сума дорівнює 1.
4. **Зайві байти в `bitstream` після закодованих даних** → `E_PAYLOAD` (неузгоджені довжини секцій, розділ 6).
5. **«Окремі дерева для різних потоків символів».** Таблиця Гаффмана будується окремо для кожного пакета. У режимі рюкзака одна таблиця будується на все вікно кандидатів і записується в кожен пакет цього вікна.
