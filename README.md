# secure_telemetry_channel

Захищений канал телеметрії з обмеженою пропускною здатністю. 

Передавач: кадри → стиснення Гаффмана → пакет TLM1 (AES-256-CTR + HMAC-SHA256) → модель каналу → приймач → ті самі кадри. Формат пакета — строго за `FORMAT_SPEC.md`, модель каналу — `channel.py`.

## Вимоги

- Python 3.10+
- залежності: `pip install -r requirements.txt` (pytest, cryptography)

## Запуск

Усі команди виконуються з кореня репозиторію.

```
pip install -r requirements.txt
python -m pytest -v
python src/run_session.py
```

`run_session.py` проганяє сеанс із `data/session.bin` (3000 кадрів) через три сценарії каналу з `data/team_config.json` і друкує S, R, T, Q. Приклад виводу:

```
Кадрів у сеансі: 3000
сценарій    пакетів  кадрів       S       R       T       Q   час, с
спокійний        79    3000  0.4751  1.0000  0.9611  0.7317     0.81
робочий          79    2924  0.4751  0.9733  0.9625  0.7226     0.78
аварійний        79    1526  0.5872  0.5067  0.9627  0.6153     0.78
```

## Рішення щодо неоднозначностей FORMAT_SPEC

Специфікація не визначає ці випадки однозначно, тому команда вирішила так:

1. **Розділ 7, «31 біт».** Вважаємо опискою: байти `0C E6 DF 90` містять 30 біт даних і 2 нулі доповнення.
2. **Ненульові біти доповнення** → `E_CODE` (помилка в бітовому потоці, розділ 3.3).
3. **Таблиця довжин із сумою Крафта ≠ 1** → `E_CODE`. Виняток: один символ із довжиною 1 (сума ½), дозволений розділом 3.2. Код Гаффмана завжди дає повне дерево; на всіх еталонних пакетах сума дорівнює 1.
4. **Зайві байти в `bitstream` після закодованих даних** → `E_PAYLOAD` (неузгоджені довжини секцій, розділ 6).
5. **«Окремі дерева для різних потоків символів».** Таблиця Гаффмана будується окремо для кожного пакета.
